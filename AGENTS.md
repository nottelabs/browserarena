# Agent notes

- Website checks: `npm --prefix web test` runs the unit tests (`web/lib/*.test.ts`). `npm --prefix web run test:layout` runs Playwright against `next start` on port 3030, so run `npm --prefix web run build` first.
- On a freshly started local server, the benchmark shell's prefetches of `/`, `/proxies`, `/throughput` and provider pages can take 20+ seconds. Client navigations (run pickers, `router.push`) wait behind them, so a picker test can time out locally and still pass in CI. An uncached day can also take about 10 seconds to render locally, so the `/proxies` layout test can time out too. Compare against `main` before treating those as regressions.
- Vercel previews are behind Vercel SSO. For scripted checks, send the project's automation bypass secret in the `x-vercel-protection-bypass` header, or use `vercel curl <path> --deployment <url>`.
- The secret is not in the repo or `.env` files. The Vercel project API (`GET /v9/projects/<id>`) lists it under `protectionBypass` with scope `automation-bypass`. `vercel curl --debug` shows the header name but not its value.
- Props passed from server to client components are serialized into the page HTML, and with `cacheComponents` the payload appears twice. Pass only the fields a client component reads; see `web/lib/history-chart-data.ts` and `proxyStatsForClient` in `web/lib/proxy-get.ts`. `web/lib/page-payload.test.ts` pins what is kept. Check page weight with `curl -s --compressed <url> | wc -c` before and after a change.
- Other local sessions may run Next.js servers on ports 3030–3032. Check `lsof -ti tcp:<port>` before starting or stopping a server.
